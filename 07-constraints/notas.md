Parte 1 — ¿Qué son los constraints?

Tenemos una tabla:

accounts
id	name	balance
1	Nequi	500000
2	Bancolombia	1200000
3	Efectivo	150000

intentan guardar 
id = 4
name = NULL
balance = -500000

¿Quién debería impedir que esos datos se almacenen?

Un constraint es una restricción definida en la base de datos que PostgreSQL comprueba para proteger la integridad de los datos.

Parte 2 — PRIMARY KEY

PRIMARY KEY garantiza dos propiedades:
1. El identificador no puede repetirse.
2. El identificador no puede ser NULL.

Parte 3 — NOT NULL

CREATE TABLE products (
    id INTEGER PRIMARY KEY,
    name TEXT
);

Aquí name permite NULL.

para eso se usa not null

CREATE TABLE products (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL
);

Parte 4 — UNIQUE

users
id	name	email
1	Carlos	carlos@example.com
2	María	maria@example.com

Queremos evitar que dos usuarios tengan el mismo correo electrónico.

CREATE TABLE users (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT UNIQUE
);

Parte 2: CHECK y DEFAULT

1. CHECK — Validar reglas de negocio

Imagina que tenemos una tabla para registrar presupuestos mensuales.

Queremos impedir que alguien registre un presupuesto negativo o igual a cero.

Para eso utilizamos CHECK

CREATE TABLE budgets (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL,
    amount NUMERIC(12,2) CHECK (amount > 0)
);

Una restricción CHECK se satisface si su condición produce TRUE o UNKNOWN.

por eso acepta null

2. DEFAULT — Valores predeterminados

CREATE TABLE budget_examples (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL,
    is_active BOOLEAN DEFAULT TRUE
);

asigna automaticamente algo si no se le da

3. ¿Y si la tabla ya existe?

ALTER TABLE budgets
ADD CONSTRAINT positive_amount
CHECK (amount > 0);

Parte 3: FOREIGN KEY

1. ¿Qué problema resuelve una FOREIGN KEY?

Imagina que tenemos dos tablas:

customers
id	name
1	Carlos
2	María

wallets
id	name	customer_id
10	Nequi	1
11	Bancolombia	1
12	Efectivo	2

Aquí customer_id indica a qué cliente pertenece cada cuenta.

¿Pero qué ocurre si intentamos crear una cuenta con customer_id = 999 y ese cliente no existe?

Una FOREIGN KEY protege la integridad referencial, impidiendo que una columna referencie un registro inexistente.

2. Cómo definimos una FOREIGN KEY

CREATE TABLE wallets (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL,
    customer_id INTEGER REFERENCES customers(id)
);

customer_id INTEGER REFERENCES customers(id)

Esto establece que customer_id referencia a la columna id de customers

También podríamos expresar la restricción separadamente:
FOREIGN KEY (customer_id) REFERENCES customers(id)

3. ¿Qué ocurre si eliminamos un cliente?

Supongamos que Carlos tiene dos cuentas y queremos eliminar su registro.

Por defecto, PostgreSQL impide que una eliminación deje referencias inválidas, siempre que existan las restricciones correspondientes.
