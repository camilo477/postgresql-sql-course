Parte 1 — ¿Qué es la cardinalidad?

1:1 — Uno a uno

Un cliente puede tener un único perfil y cada perfil pertenece a un solo cliente.


1:N — Uno a muchos

Un cliente puede tener muchas cuentas. Cada cuenta pertenece a un cliente.


N:M — Muchos a muchos

Bloque 08 — Parte 3: ON DELETE y ON UPDATE

Imagina estas tablas:

customers
id	name
1	Carlos
2	María

wallets
id	name	customer_id
10	Nequi	1
20	Bancolombia	1
30	Efectivo	2

Carlos tiene dos cuentas.

¿Qué ocurre si ejecutamos?
DELETE FROM customers
WHERE id = 1;

Comportamientos principales
Opción	Qué hace
NO ACTION	Comportamiento predeterminado. Impide dejar referencias inválidas; la comprobación puede diferirse si la restricción es diferible.
RESTRICT	Impide eliminar el registro referenciado mientras existan referencias.
CASCADE	Elimina automáticamente los registros relacionados de la tabla hija.
SET NULL	Establece la FK de los registros relacionados en NULL.
SET DEFAULT	Establece la FK en su valor predeterminado, que debe seguir siendo válido.

Ejemplo: ON DELETE CASCADE
CREATE TABLE wallets (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL,
    customer_id INTEGER NOT NULL
        REFERENCES customers(id)
        ON DELETE CASCADE
);


Si eliminamos a Carlos, PostgreSQL también eliminará sus dos registros de wallets.

¿Es recomendable CASCADE en una aplicación financiera?
Depende de las reglas del negocio.

Si eliminamos un usuario, quizá no queremos perder automáticamente sus cuentas y su historial financiero.

2. ON DELETE SET NULL
Otra posibilidad es:
customer_id INTEGER
    REFERENCES customers(id)
    ON DELETE SET NULL


Si eliminamos al cliente, PostgreSQL conserva sus cuentas, pero establece customer_id = NULL.

3. ON UPDATE
Ahora imaginemos que el identificador de Carlos cambia de 1 a 100.

Tenemos:
customers.id = 1

wallets.customer_id = 1


Si configuramos:
customer_id INTEGER
    REFERENCES customers(id)
    ON UPDATE CASCADE


Y modificamos la clave referenciada:
UPDATE customers
SET id = 100
WHERE id = 1;


PostgreSQL también actualiza las referencias correspondientes en wallets.
